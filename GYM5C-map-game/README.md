# 狀態模式——二維地圖冒險遊戲

## 📌 系統簡介
本專案為一款回合制的 **二維地圖冒險遊戲 (State-Based Map Adventure Game)**。玩家操控主角在隨機生成的地圖上移動、攻擊怪物並拾取寶物，角色會因為拾取寶物或受到攻擊而進入各種狀態（無敵、中毒、加速、恢復、混亂、蓄力、爆發、瞬身），而每種狀態都會改變角色的行動方式、攻擊範圍、受傷反應與回合效果。

透過狀態模式 (State Pattern)，將這些「隨狀態而變」的行為封裝在獨立的 `State` 類別中，讓角色本身不需要充滿 `if (state == ...)` 的判斷，新增狀態時也不必修改 `Map`、`Character`、`Monster`、`Role` 等既有類別。

---

## 🛠️ 核心規則與系統功能

### 1. 地圖與地圖物件
- **地圖 (Map)**：預設為 `10 × 20` 的二維網格，每一格最多只能放一個地圖物件。
- **地圖物件 (MapObject)**：遊戲開始時隨機放置在空格上：
  | 物件 | 符號 | 數量 | 說明 |
  | :--- | :---: | :--- | :--- |
  | 主角 (Character) | `↑ ↓ ← →` | 1 | HP 300，符號代表目前面朝的方向 |
  | 怪物 (Monster) | `M` | 地圖格數 × 5% | HP 1，攻擊力 50 |
  | 寶物 (Treasure) | `x` | 地圖格數 × 2.5% | 依生成機率隨機決定種類 |
  | 障礙物 (Obstacle) | `□` | 地圖格數 × 2.5% | 不可通過，也會阻擋主角的攻擊 |

### 2. 回合流程
每一回合依序進行：
1. **狀態效果階段**：主角與所有怪物觸發目前狀態的回合效果（如中毒扣血、恢復補血），並倒數狀態剩餘回合。
2. **顯示階段**：印出地圖，以及主角的 HP、目前狀態與狀態剩餘回合。
3. **主角行動**：玩家選擇「攻擊」或「移動（上下左右）」，行動次數依狀態而定（加速時每回合可行動兩次）。
4. **移除死亡怪物**：若怪物全數陣亡，玩家獲勝。
5. **怪物行動**：主角在怪物的攻擊範圍內就攻擊，否則隨機往一個方向移動。
- 主角 HP 歸零時，遊戲結束，玩家落敗。

### 3. 攻擊與觸碰
- **主角攻擊**：朝面向的方向發射一整條直線攻擊，線上的怪物都會受到傷害，但攻擊無法穿越障礙物。
- **怪物攻擊**：只能攻擊上下左右相鄰一格內的主角，每次造成 50 點傷害。
- **觸碰 (Touch)**：角色往某個方向移動時，若目標格已有其他物件，則改為「觸碰」該物件。觸碰到寶物時會進入寶物對應的狀態，寶物也會從地圖上消失。

### 4. 寶物與狀態
| 寶物 | 生成機率 | 進入狀態 |
| :--- | :---: | :--- |
| 無敵星星 (SuperStar) | 10% | 無敵 (Invincible) |
| 毒藥 (Poison) | 25% | 中毒 (Poisoned) |
| 加速藥水 (AcceleratingPotion) | 20% | 加速 (Accelerated) |
| 補血罐 (HealingPotion) | 15% | 恢復 (Healing) |
| 惡魔果實 (DevilFruit) | 10% | 混亂 (Orderless) |
| 王者之印 (KingsRock) | 10% | 蓄力 (Stockpile) |
| 任意門 (DokodemoDoor) | 10% | 瞬身 (Teleport) |

### 5. 狀態效果表
| 狀態 | 持續回合 | 效果 |
| :--- | :---: | :--- |
| 一般 (Normal) | - | 預設狀態，每回合行動一次。 |
| 無敵 (Invincible) | 2 | 受到攻擊時不會損失生命值。被怪物攻擊後也會進入此狀態。 |
| 中毒 (Poisoned) | 3 | 每回合開始時損失 15 點生命值。 |
| 加速 (Accelerated) | 3 | 每回合可以行動兩次；期間若受到攻擊，立刻回到一般狀態。 |
| 恢復 (Healing) | 5 | 每回合開始時恢復 30 點生命值，直到滿血；滿血時立刻回到一般狀態。 |
| 混亂 (Orderless) | 1 | 無法自行選擇行動，只能隨機往上下左右其中一個方向移動。 |
| 蓄力 (Stockpile) | 2 | 結束後進入爆發狀態；期間若受到攻擊，立刻回到一般狀態。 |
| 爆發 (Erupting) | 1 | 攻擊範圍擴大到全地圖，攻擊力變為 50；結束後進入瞬身狀態。 |
| 瞬身 (Teleport) | 1 | 回合效果觸發時，角色被隨機傳送到地圖上任一空格。 |

狀態結束後，除非另有指定的下一個狀態（蓄力 → 爆發 → 瞬身），否則都會回到一般狀態。

## 🎯 設計需求（非功能性需求）

- **消除狀態判斷**：角色在不同狀態下的行動、攻擊範圍、移動方式與受傷反應各不相同，必須避免在 `Role` 中堆疊大量 `if-else` / `switch` 判斷。
- **開閉原則 (OCP)**：新增狀態時，不需修改 `Map`、`Character`、`Monster`、`Role` 等類別的程式碼。
- **狀態轉換內聚**：每個狀態自己負責持續回合的倒數，以及結束或被打斷時要轉換到哪個狀態。

## 📊 OOA / OOD 設計與 UML 架構

本專案採用 **狀態模式 (State Pattern)**，讓 `Role` 把行為委派給目前持有的 `State` 物件；寶物則以 **工廠方法 (Factory Method)** 的形式，透過 `createState()` 決定要產生哪一種狀態。相關圖檔與設計說明如下：

### 1. OOA 分析階段圖
* **檔案連結**：[OOA UML 圖檔](./docs/ooa_uml.png)
* **說明**：
  * **行為變動性 Force**：`Role` 的 `state` 屬性處於不同狀態時，會讓多個行為跟著改變。例如 `takeDamage()` 在無敵和中毒狀態下不同，`generateStateEffect()` 在加速和恢復狀態下也不同。
  * **擴充性 Force**：擴充新狀態時，`Map`、`Character`、`Monster`、`Role` 類別都應遵守 OCP，不用修改既有程式就能加入新狀態。
  * **Problem**：若以字串保存狀態，並在 `Role` 的每個方法中判斷目前狀態，狀態與行為的組合會讓程式快速膨脹，每新增一個狀態都要回頭修改多處程式碼。

### 2. OOD 設計階段圖
* **檔案連結**：[OOD UML 圖檔](./docs/ood_uml.png)
* **說明**：
  * 導入 **State Pattern**：定義抽象類別 `State`，提供 `action()`、`attackRange()`、`moveTarget()`、`takeDamage()`、`touch()` 的預設行為，以及狀態生命週期的掛鉤 `enterState()`、`exitState()`、`effect()`、`effectEnd()`。
  * 各具體狀態（`Normal`、`Invincible`、`Poisoned`、`Accelerated`、`Healing`、`Orderless`、`Stockpile`、`Erupting`、`Teleport`）只覆寫自己需要改變的行為。例如 `Erupting` 覆寫 `attackRange()` 讓攻擊範圍擴大到全地圖，`Orderless` 覆寫 `action()` 與 `moveTarget()` 強制隨機移動。
  * `Role` 透過 `enterState(state)` 統一進行狀態轉換：先呼叫舊狀態的 `exitState()`，再換上新狀態並呼叫 `enterState()`。`generateEffect()` 負責倒數 `countdown`，歸零時呼叫 `effectEnd()` 決定下一個狀態。
  * `Treasure` 的 `onTouched()` 為共用流程（進入狀態、從地圖移除），各寶物只需實作 `createState()` 回傳對應狀態。

### 3. 系統循序圖 (Sequence Diagram)
* **檔案連結**：[循序圖圖檔](./docs/ood_sequence_diagram.png)
* **說明**：
  * 描繪 `Game.start()` 依序生成地圖、主角、怪物、寶物與障礙物後進入 `nextRound()`；回合中主角移動到空格，怪物則移動到寶物所在格而觸發 `touch()`，再由 `Treasure.onTouched()` 呼叫 `enterState(invincible)` 讓怪物進入無敵狀態，並透過 `Map.remove()` 將寶物從地圖移除，最後判斷遊戲是否結束的時序。
