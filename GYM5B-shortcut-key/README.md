# 指令模式——快捷鍵設置機制

## 📌 系統簡介
本專案為一個模擬軍用主控室的 **快捷鍵設置與控制器系統 (Command-Based Main Controller)**。透過指令模式 (Command Pattern)，允許操作員將鍵盤 (`a-z` 共 26 個按鍵) 靈活綁定至不同的軍用裝置操作或特殊系統功能，並完整支援操作的 **Undo (還原)**、**Redo (重做)** 以及進階的 **巨集 (Macro)** 指令串連。

---

## 🛠️ 核心規則與系統功能

### 1. 裝置與操作
- **主控制器 (MainController)** 具備 26 個按鍵 (`a-z`) 的鍵盤。
- **支援的軍用裝置與動作**：
  1. **坦克 (Tank)**：向前移動 (`Move Forward`)、向後移動 (`Move Backward`)。
  2. **通訊設備 (Telecom)**：連線 (`Connect`)、關閉連線 (`Disconnect`)。
- **特殊操作**：
  - **重置 (Reset)**：可將某個按鍵綁定為「重置所有快捷鍵的設置」。

### 2. 歷史紀錄與狀態控制 (Undo / Redo)
- **Undo (還原)**：復原上一步執行的指令（支援連續 Undo 直到初始狀態）。例如坦克前進三次，Undo 三次則會執行對應的反向動作。
- **Redo (重做)**：重做被還原的指令（支援連續 Redo 直到最新狀態）。

### 3. 進階需求：指令巨集 (Macro)
- **巨集定義**：允許一個按鍵綁定**多個連續操作**（例如按下 `q` 鍵同時執行：先連接通訊設備，再讓坦克向前移動五次）。
- **完整支援**：巨集指令同樣必須完美支援 **Undo** 與 **Redo** 功能。

---

## 🎯 設計需求（非功能性需求）

- **命令解耦與封閉**：透過指令模式將請求發送者 (`MainController`) 與具體接收者（軍用裝置操作）完全解耦。
- **擴充性**：新增裝置、新操作或巨集組合時，控制器核心程式不需大幅修改。

---

## 📊 OOA / OOD 設計與 UML 架構

本專案採用 **指令模式 (Command Pattern)** 與歷史堆疊（Command History / History Stack）來實現操作封裝與復原機制，相關圖檔與設計說明如下：

### 1. OOA 分析階段圖
* **檔案連結**：[OOA UML 圖檔](./docs/ooa_uml.png)
* **說明**：
  * **行為變動性 Force**：按鍵對應的操作類型繁多（單一裝置動作、系統 Reset、多步驟巨集），且未來可能新增更多裝置。
  * **擴充性 Force**：新增按鍵功能或巨集時，不應改動主控制器的按鍵觸發核心。
  * **Problem**：若在控制器內用大量的 `if-else` 去判斷按鍵行為並手動維護狀態，將無法乾淨地實作 Undo/Redo 與動態綁定。

### 2. OOD 設計階段圖
* **檔案連結**：[OOD UML 圖檔](./docs/ood_uml.png)
* **說明**：
  * 導入 **Command Pattern**：定義抽象的 `Command` 介面（包含 `execute()` 與 `undo()` 方法），並讓各種動作實作成具體指令類別（如 `MoveForwardCommand`、`MacroCommand` 等）。主控制器只需持有指令對照表與操作歷史堆疊。

### 3. 系統循序圖 (Sequence Diagram)
* **檔案連結**：[循序圖圖檔](./docs/ood_sequence_diagram.png)
* **說明**：
  * 描繪當操作員按下鍵盤按鍵時，主控制器如何查詢對應的 Command、執行 `execute()` 並將指令推入歷史堆疊；或是當觸發 Undo/Redo 時，如何從堆疊中取出指令並正確呼叫狀態還原的時序。
