# 觀察者模式——YouTube 訂閱機制

## 📌 系統簡介
本專案為一個模擬 **YouTube 頻道 (Channel)** 與 **頻道訂閱者 (Subscriber)** 互動的 DEMO 程式。透過觀察者模式 (Observer Pattern)，當頻道上傳新影片時，能夠自動發送通知給所有訂閱者，而每位訂閱者能根據自身邏輯做出不同的反應（如按讚、解除訂閱等）。

---

## 🛠️ 核心規則與模擬測資

### 1. 基礎實體
- **YouTube 頻道**與**訂閱者**皆擁有名稱 (`name`)。
- **影片 (Video)** 屬性包含：標題 (`Title`)、敘述 (`Description`)、影片長度 (`Length`)。

### 2. 訂閱者行為邏輯
1. **水球**：
   - 收到新影片通知時，若影片長度 $\ge$ 3 分鐘，則對該影片**按讚 (Like)**；否則置之不理。
2. **火球**：
   - 收到新影片通知時，若影片長度 $\le$ 1 分鐘，則對該頻道**解除訂閱 (Unsubscribe)**。

### 3. 測試流程 (Given / When / Then)
- **初始佈局**：
  - 頻道：`PewDiePie`、`水球軟體學院`
  - 用戶：`水球`、`火球`
- **動作與事件序列**：
  1. 水球與火球皆訂閱兩頻道。
  2. 水球軟體學院上傳 `"C1M1S2"`（4 分鐘）$\to$ 水球按讚。
  3. PewDiePie 上傳 `"Hello guys"`（30 秒）$\to$ 火球解除訂閱 PewDiePie。
  4. 水球軟體學院上傳 `"C1M1S3"`（1 分鐘）$\to$ 火球解除訂閱水球軟體學院。
  5. PewDiePie 上傳 `"Minecraft"`（30 分鐘）$\to$ 水球按讚。

## 🎯 設計需求（非功能性需求）

- **開閉原則 (OCP)**：當未來需要**實作新的訂閱者**或新增不同的訂閱反應行為時，YouTube 頻道必須對修改關閉、對擴充開放（不需修改頻道核心程式碼）。

---

## 📊 OOA / OOD 設計與 UML 架構

本專案採用 **觀察者模式 (Observer Pattern)** 來解耦頻道與訂閱者之間的通知依賴，相關圖檔與設計說明如下：

### 1. OOA 分析階段圖
* **檔案連結**：[OOA UML 圖檔](./docs/ooa_uml.png)
* **說明**：
  * **行為變動性 Force**：每位訂閱者收到通知時的反應邏輯各異，且未來會持續新增不同類型的訂閱者。
  * **擴充性 Force**：新增訂閱者類型時，頻道不應需要更改既有的廣播或通知程式碼。
  * **Problem**：若頻道直接依賴具體的訂閱者實作，會造成強耦合且無法動態擴充。

### 2. OOD 設計階段圖
* **檔案連結**：[OOD UML 圖檔](./docs/ood_uml.png)
* **說明**：
  * 導入 **Observer Pattern**：定義抽象的 `Observer`（或 `Subscriber`）介面，讓 `Channel`（Subject）僅需維護觀察者清單並統一呼叫通知方法，由具體訂閱者子類別 (`WaterSubscriber`, `FireSubscriber`) 自行實作對應的過濾與互動邏輯。
